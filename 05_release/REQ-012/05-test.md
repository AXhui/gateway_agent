## 2. 验收标准

| 功能 | 通过条件 |
|---|---|
| 入网失败状态 | OTAA 密钥错误/超时未上行、ABP 密钥错误三类场景下，设备状态均为「入网失败」且右侧原因正确（密钥错误/节点未收到入网应答包）；无「未收到JoinRequest」类原因；原因不作为独立状态 |
| 在线判定 | OTAA 需 Join Accept 后超时窗口内收到正常上行（重复 JoinRequest 不计）；ABP 上行解析正常即在线 |
| 默认密钥 OTAA | 动态优先→固定回退→双失败报 Key 错误；成功 Key 用于 JoinAccept 生成 |
| ABP 默认参数 | DevEUI `24e124136e445120` 生成 DevAddr `e445120*`；首次上行校验成功后密钥持久化绑定，后续直用绑定密钥，下行同密钥加密 |
| 激活设置 | Milesight 判定（24E124 前缀/型号）驱动默认选中；非 Milesight「默认值」禁用；切换保留输入；ABP 默认值置灰三字段且帧计数/超时可编辑 |
| 编辑页切换 | 场景 1/2/3 的状态与字段值行为完全符合 04-dev §3.8 表；暂存恢复、保存清除生效 |
| 历史兼容 | 旧版本升级后 DevAddr 保留且标记自定义值 |
| 扫描配置 | 无 Key 置灰；Key ≤1000；导入 4 类失败横幅文案逐字正确且行为正确（非法全失败、重复不去重、超限提示 N 正确）；清空不影响默认 Key；AppKey 备份还原/升级保留 |
| 全局提示条 | 扫描中全页可见；红点/计数/变灰状态机正确；点击跳转不中断扫描 |
| 扫描确认页 | 双 Tab 流转正确；字段默认值与过滤功能齐全；行内/单/多编辑约束生效（ABP 配置文件被过滤）；添加成功/冲突/无型号行为正确；2000/20000 上限生效；URL 直入 3 秒跳回 |
| 扫描逻辑 | 本地设备忽略、池内更新、MIC 顺序匹配、全失败不记录、静默扫描不发 Join Accept、添加后才发 |
| 纯净排除 | 不含数据埋点实现；ABP 无 AppKey 输入框 |

## 3. 数据校验点

| 输入 | 期望输出 | 来源 |
|---|---|---|
| DevEUI = `24e124136e445120`（ABP 默认值） | DevAddr = `e445120*`（截取第 10-16 位 + 附录 4.1 算法校验位） | PRD §2.2.1 示例 |
| 固定密钥 | `5572404c696e6b4c6f52613230313823`（OTAA/ABP 通用） | PRD §2.1.1/§2.2.2 |
| 动态密钥 | DevEUI + DevEUI 拼接（待确认是否直接拼接） | PRD §2.1.1/§2.2.2 |
| 校验位算法参数 | encryptString/decryptString 映射表、keyForCode=YEASTAR、初值 0x12、ADD=1/SUB=2、mod 10 + 0x30 | PRD 附录 4.1 |

## 7. 风险点提示

| # | 风险 | 说明 |
|---|---|---|
| 1 | MIC 逐 Key 匹配性能 | 最坏 1002 把 Key × Join Request 高频重试，NS 侧 CPU 与时延敏感 |
| 2 | 静默扫描下的无线风暴 | 扫描中不下发 Join Accept，设备侧会持续重发 Join Request（占空比/信道占用），扫描时长与设备数量需关注 |
| 3 | 多用户并发添加竞态 | 冲突不强制拦截，依赖提交时校验；同批部分冲突部分成功的状态一致性 |
| 4 | 2000 覆盖最旧丢数据 | 被覆盖设备无预警丢失；已忽略设备是否也被覆盖口径未明（04-dev 疑点 10） |
| 5 | DevAddr 生成位数疑点 | 「6 位/7 位」矛盾若按错误口径实现，将导致 ABP 默认参数设备全部无法通信（高优先级确认项） |
| 6 | 动态密钥可预测性 | DevEUI+DevEUI 直接拼接可预测，安全评估需产品/安全侧知悉 |
| 7 | 升级兼容遗漏 | activationMode 标记仅覆盖 ABP 历史设备；OTAA 历史设备的默认/自定义默认值口径需验证 |
| 8 | 3 秒跳转与用户操作竞态 | URL 直入弹窗倒计时期间用户其他操作的行为未定义 |
| 9 | 暂存逻辑边界 | 未保存切换多轮（A→B→A→B）后暂存一致性；与场景 2/3 带入值的叠加 |
| 10 | 提示文案硬编码 | 4 条导入横幅与 3 条反馈文案需逐字验收，含变量 N/xx 的动态正确性 |
| 11 | 全局提示条与页面框架冲突 | 所有页面挂载，需回归各页布局不被破坏（尤其状态页，V0.3 专门修订） |
