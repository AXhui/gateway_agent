# 文档规则 · Documentation

> **适用范围**：基础组件与业务组件**共用一份模板**。
> **性质**：硬性约束。每个组件的 SKILL.md 必须填满 8 个章节；业务组件额外要求已在各节标注。

## 0. 统一模板（8 章节）

所有组件（基础 + 业务）的 SKILL.md 必须包含以下 **8 个章节**，顺序固定，缺一打回：

| # | 章节 | 内容 | 基础 | 业务 |
|---|------|------|:----:|:----:|
| 1 | **描述** | 组件定位（一句话）+ 用途边界 | ✅ | ✅ |
| 2 | **Props** | Props 契约表（参数/类型/默认值/说明） | ✅ | ✅（业务改为「组装契约」） |
| 3 | **状态** | 交互/视觉状态（hover/active/disabled/loading/error…） | ✅ | ✅ |
| 4 | **场景** | 何时用 / 何时不用（改用哪个组件） | ✅ | ✅ |
| 5 | **Token** | 使用的 L1 设计令牌清单 | ✅ | ✅ |
| 6 | **依赖** | 上游依赖（基础：导入方式；业务：atoms 依赖序列） | ✅ | ✅ |
| 7 | **示例** | 代码示例（最小可运行） | ✅ | ✅ |
| 8 | **版本** | 版本号（指向前端 frontmatter `version:`，见 versioning.md） | ✅ | ✅ |

> 现有 SKILL.md 的历史标题（基础「产品层/UED 层/研发层」、业务「业务层/组装层/研发层」）需**逐步收敛**到上表 8 章节；迁移期内允许在旧标题下按 8 章节内容补齐，但新组件必须直接用 8 章节。

## 1. 描述（Description）

- 一句话定义「这是什么」，一句话定义「不是什么」。
- 业务组件须写清**归属产品线**（`eg71` / `router` / `cctv` / `cv` / `com`）与 `entityHint`（如 `gateway`）。

## 2. Props（Props 契约）

- 基础组件：标准 Props 表，含 `antd` 别名（若有）。
- 业务组件：改为**组装契约**——`atoms` 依赖序列（依赖哪个 `S_*`、对应 `ms-*` 控件、作用）+ `ctx` 上下文契约（`ctx.route` 等单一来源）。

## 3. 状态（States）

- 基础组件：五轴交互态（hover / active / keyboard / loading / error），逐态给出 token 映射（如 disabled → `opacity 0.5`）。
- 业务组件：可交互态（如侧边栏 `is-collapsed` 展开/收起），给出类切换 + aria 同步（`aria-expanded` / `aria-label`）。

## 4. 场景（Scenarios）

- 「何时用」列出触发条件；「何时不用」用表格给出**改用哪个组件**（不写「别用」了事，必须给出替代）。

## 5. Token（设计令牌）

- 列出本组件用到的**全部** `--*` 变量（色/圆角/间距/字号/阴影/时长/缓动），逐条列全。
- 规则：只许用 L1 令牌，出现硬编码值即违反 encapsulation.md 第 3 条。

## 6. 依赖（Dependencies）

- 基础组件：导入方式（React + esm.sh importmap）、无其他运行时依赖。
- 业务组件：`atoms` 依赖序列（表），并声明「不新增基础原子，仅编排」。

## 7. 示例（Examples）

- 最小可运行代码片段，基础组件给 JSX/HTML，业务组件给 render 骨架 + bind 骨架。

## 8. 版本（Version）

- **不在此处重复写版本号**，只写「见 frontmatter `version:`」。正文与 frontmatter 二选一，权威源是 frontmatter（见 versioning.md）。

## 附：业务组件补充

业务组件的文档若有产品线特有字段（页面验证、跨产品线影响），在 `.claude/rules/business-specific.md` 追加，**不重写本模板**。
