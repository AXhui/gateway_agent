# 业务组件补充规则 · Business-specific Supplement

> **定位**：本文件是 `../rules/` 的**差异补充**，不是重写。通用规则（encapsulation / versioning / naming / documentation / release）已共用一份，本文件只写**业务层独有**的那 ~10%。
> **叠加关系**：组件级元数据 > 本补充规则 > `../rules/` 通用规则。

## 1. 样式铁律（对应 encapsulation.md §3 的业务特化）

业务组件**只编排、不写样式常量**：

- ✅ 允许：组合 `S_*` 原子的 `ms-*` 类；引用 L1 token 变量；用 `bc-*` 结构类控制布局/显隐。
- ❌ 禁止：新增颜色/字号/间距/阴影常量；发明新的 `ms-*` 类；在业务层定义 `--*` 变量。
- 判断：业务组件里若出现一个既非 `ms-*` 也非 `bc-*`、又非 `--*` 引用的样式值 → 打回，下沉到 L1/L2。

## 2. 组装契约（对应 documentation.md §2 的业务特化）

业务组件的 Props 契约 = **组装契约**，必须包含：

1. `atoms` 依赖序列（表）：依赖哪个 `S_*`、对应 `ms-*` 控件、在本组件的作用。
2. `ctx` 上下文契约：业务组件依赖的单一来源（如 `ctx.route`、`ctx.entity`），只读，变更走回调。
3. `render(ctx)` 骨架 + `bind(root)` 骨架：可空跑、幂等。
4. `entityHint`：归属实体（`gateway` / `device` / `channel` …）。

## 3. 产品线前缀（对应 naming.md §2.4 的业务特化）

- 业务组件名必须带产品线/域前缀：`eg71` / `router` / `cctv` / `cv` / `com`（跨线通用）。
- 目录归属：`business/eg71/`、`business/router/`、`business/cctv/`、`business/cv/`、`business/_shared/`（com 前缀）。
- 运行时 id 一律 `bc-<域>-<组件>`。

## 4. 发布追加两条（对应 release.md §3）

- **产品线实际页面验证**：业务组件必须在其归属产品线真实页面（如 EG71 网关后台）端到端跑通一次，含真实数据 + 交互。
- **跨产品线影响评估**：改 `bc-com-*` 等共用组件时，评估对 eg71/router/cctv/cv 四线回归影响并同步验证。

## 5. 表单布局（表单类业务组件编排补充）

业务组件渲染表单时，控件排列遵守三条，全部用既有 L2 结构类（`ms-form-item` / `ms-grid-2`）表达，不新增样式常量：

### 5.1 控件高度统一

- 同一表单（同一 `ms-form` 或同一卡片内）的所有输入类控件（`ms-input` / `ms-select` / 日期选择等）必须使用**同一高度档位**，表单默认档 **40px**（`ms-input--lg` / `ms-select--lg`）；确需紧凑时整个表单统一降标准档 32px（无修饰符默认类）。
- 判断：同一表单内出现 40px 与 32px（或 28px）控件并列 → 打回。
- 例外：textarea（`ms-input--textarea`，高度自适应）与按钮不受此约束。

### 5.2 双列布局（一左一右）

- 表单项较多时（经验阈值：同一分组/卡片内 **> 6 项**），表单改**双列**排布——`ms-grid-2` 包裹 `ms-form-item`，一左一右、逐行换行。
- **列间距 32px**（`--spacing-3xl`；Figma「.启用/禁用功能逻辑」页 Form 双列真源：两列各 600/580px 宽、gutter 32px）。落地：`ms-grid-2` 上叠加 `bc-com-form-grid` 结构类（`library/business.css`，仅覆写 column-gap，行间距仍 16px）。
- 内容较少（≤ 6 项）、含长文本域（textarea）或天然宽控件（IP 段、时间范围等）的表单保持**单列**。
- 禁止用 float / 手写两栏 flex 模拟双列——双列只有 `ms-grid-2`（表单场景 + `bc-com-form-grid`）一种表达。

### 5.3 影响布局的选择框单独成行

- 某选择框（`ms-select`）的取值**影响下方字段布局**（联动显隐、级联切换后续表单项）时，允许该选择框**单独成行**：独占一行，后续表单项从下一行重新起列。
- 该选择框**宽度仍为一列宽**，禁止拉伸通栏——保持下方双列的对齐节奏不被打断。
- 不影响布局的普通选择框照常参与双列排布，不得借此单独成行。
- 典型场景是**级联/模式类**选择（取值决定下方字段集）；表单内的启用/禁用**不走选择框**，字段组启停用 checkbox / 双箭头表达（载体分工见 §6.1）。

## 6. 启用禁用联动（跨表单与表格标题的统一逻辑）

启用/禁用是**跨场景的同一台状态机**，不是表单、表格各自的私有规则：一个载体管辖一个区块的可用性，被管辖区块不可交互、状态保持。**设计真源**：Figma 业务组件库「.启用/禁用功能逻辑」页（网关/路由器通用业务组件库）。本节按「启用禁用」逻辑轴统一约束；表单（§5）与表格/卡片标题（AGENTS.md 标题契约的开关位）只是它的落点。

### 6.1 载体分工（按层级选载体，禁止跨层混用）

| 层级 | 载体 | 位置 | 规范（Figma 原文语义） |
|---|---|---|---|
| 大标题/次标题级（**总闸**） | **switch**（`ms-switch--xs` 28×16） | 跟在大标题/次标题的**右侧**（标题契约：紧跟标题组、不在行尾） | 管辖标题下方整块内容（表格或表单） |
| 字段组/内容行级 | **checkbox** | 跟在内容**左侧**、单行展示 | 无附加内容：点击勾选即可；有附加内容：勾选后附加内容**内缩 20px**（`--spacing-xl`）展开，禁用时**收起** |
| 字段组/内容行级（变体） | **双箭头** | 跟在内容左侧、单行展示 | **必须有附加内容**才可使用；点击内缩 20px 展开展示，再次点击收起 |
| 下拉**级联**（非启停） | `ms-select` | 照常参与表单排布（影响布局时按 §5.3 单独成行） | 取值切换下方字段集是**级联显隐**，不是启用/禁用；不得拿 checkbox 冒充级联选择，也不得拿 select 冒充启停开关 |

- **多选嵌套**：展开的附加内容本身全是 checkbox 多选组时成立——内层 checkbox 是**取值控件**，不是第三层启停开关。
- 附加内容的内缩容器由该字段组自身的 `bc-<域>-<块>` 容器类承载（`padding-left: var(--spacing-xl)`），不新增样式常量。

### 6.2 状态机与视觉（按载体分态）

| 载体 | 启用 | 禁用 |
|---|---|---|
| switch（标题总闸） | on：区块正常交互 | off：区块挂 `--disabled` 修饰符**整体灰显**（opacity 0.45 + pointer-events: none），内容保持可见 |
| checkbox / 双箭头（字段组） | 勾选/展开：附加内容展示、可交互 | 取消/收起：附加内容**收起**、值不清空 |

- 被管辖区块统一挂**自身 BEM 修饰符** `bc-<域>-<块>--disabled`（既有范式：`bc-eg71-snmp-fields--disabled` / `bc-eg71-plan-card--disabled` / `bc-eg71-event-body--disabled`，视觉值以这三处既定范式为准，不另造新值）。
- 禁止页面层手写 opacity / pointer-events 内联灰显绕过修饰符。
- **状态保持**：重新启用后恢复禁用前的值与字段级开关状态，不重置、不清空；checkbox 收起再展开同理，附加内容原样回来。
- 切换反馈与失败回滚遵循 `interaction-completeness.md` §1（开关/启停行）。

### 6.3 互相制约（总闸优先，层级只有两级）

1. **总闸关 → 区块内一切不可用**：字段级 checkbox、级联选择框、输入控件随区块整体灰显；禁止「总闸关了字段还能改」。
2. **总闸开 → 字段级自治**：字段级 checkbox / 双箭头按 §6.1 管辖自己的附加内容。
3. **层级只有两级**：总闸（标题 switch）→ 字段级（checkbox / 双箭头）；附加内容里的多选 checkbox 是取值控件，不算第三层管辖（§6.1）。
4. **两级状态独立保存**：总闸切换不改动字段级开关的 on/off，只冻结其可交互性；恢复启用后字段级状态原样回来。

### 6.4 单行同类唯一（红线）

同一业务行（标题行 / 字段组行 / 内容行）内，**同类载体与标识元素至多一个**，重复并列即打回：

- ❌ 违规形态：`checkbox checkbox …`（两个勾选载体同行）、`switch switch …`、`双箭头 双箭头 …`、`标题 标题`（同行重复主/次标题）、两组同款「图标 + 文字」并列。
- 理由：载体唯一，管辖归属才唯一（§6.1 载体分工）；同类重复并列后，用户无法判定哪个控件管辖本行。
- 业务确需两个独立启停 / 两个标题 → **拆成两行**，禁止同行并列。
- 不受此限：按钮组、标签组、表格操作列、多选 checkbox 组等**集合类控件**——它们并列的是不同操作/取值（含 §6.1 多选嵌套的内层取值 checkbox），不是管辖载体。

## 7. 本层边界

- 本文件**不重复** encapsulation / versioning / naming / documentation / release 的任何通用条目。
- 若某条业务差异未来被多线共用、可抽象为通用规则，则**上沉**到 `../rules/`，从本文件删除——规则只升不裂。
