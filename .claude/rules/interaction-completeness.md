# 交互链完整性与 PRD 反馈闭环 · Interaction Completeness & PRD Feedback Loop

> **适用范围**：一切按 PRD 生成的 demo——A4 渲染（补全交互链）、A5 校验（缺口判定）、A6 反馈（多维表格 issue 台账 + PRD 文档评论回写）。
> **性质**：硬性约束。demo 不允许只渲染 PRD 字面写到的「正向路径」；PRD 有缺口时 demo 补全链路，同时把缺口**反向评论回 PRD 文档**，形成「PRD → demo → 校对 → PRD」闭环。
> **与既有文档的关系**：`page-assembly.md` 管 demo 怎么拼（L3 装配 + 纯净性），本文件管 demo 拼完后**链路是否完整**以及**缺口如何回流 PRD**；`K_validation.md` 的 R5 / 纯净性校验挂钩本文件。

## 1. 交互链完整性红线（A4 渲染时执行）

**每个 PRD 功能点必须落成完整交互链**：

```
入口（怎么触达）→ 操作（点/输/选）→ 即时反馈（loading/校验）→ 结果态（成功 / 失败 / 空 / 边界）
```

1. **必备状态集**（按功能点裁剪，逐项核对）：
   | 功能点类型 | 必备状态 |
   |---|---|
   | 列表/表格 | 加载中 / 空态 / 数据态 /（涉及删除时的）危险确认 |
   | 表单 | 未填默认态 / 校验失败态 / 提交中 / 提交成功反馈 |
   | 操作按钮 | 默认 / hover / loading（异步时）/ 危险操作的确认弹窗（`B_Eg71Modal` / `B_ComDangerAction`） |
   | 开关/启停 | 切换反馈 + 失败回滚提示 |
   | 数据同步/下发 | 进行中 / 成功 / 超时失败 |

2. **PRD 未写但链路必需的状态：允许且必须补全**——用资产库既有组件补（映射清单标注 `【PRD 缺省 · demo 补全】`），补全原因与形态记入 `validation.md`，**不进可见 UI**（纯净性不变，page-assembly.md §5）。
3. **补全边界（判断红线）**：只补**链路必需态**（loading / error / empty / 确认），**不发明 PRD 没有的功能、入口、业务规则**。PRD 写「A 功能」而你觉得 A 缺一个业务能力（如缺权限分支、缺失败后的业务去向）→ 那不是补全项，是 §2 的 C/D 类缺口，走评论回流，demo 不擅自实现。

## 2. 缺口分类（A5 校验时逐功能点产出）

| 类别 | 判定 | demo 处理 | PRD 反馈 |
|---|---|---|---|
| **A 完整** | 链路五态齐 | 无 | 无 |
| **B 链路断** | 缺 loading / error / empty / 确认等必要状态 | demo 补全（§1.2） | 记 issue → 评论「建议补充」 |
| **C 描述不完整/矛盾** | PRD 对某状态的行为没写或两处冲突 | demo 按 PRD 字面实现，缺的状态用最小合理默认 | 记 issue → 评论「需要澄清」 |
| **D 隐含缺失** | PRD 没提但产品上必需（权限、边界值、失败业务去向） | 小缺口（纯 UI 态）→ 补全；大缺口（涉业务规则）→ **不实现**，占位为 PRD 字面形态 | 记 issue → 评论「建议 PRD 增补」 |

- 缺口清单落在 `05_release/REQ-###/validation.md` 专节「交互链缺口（A5）」，每条含：功能点 / 类别 / 缺什么 / demo 处理 / 建议给 PRD 的话术。
- **断链（B 类）未补全即校验不过，退回 A4**；缺口存在但未记 issue → A5 视为校验未完成。

## 3. issue 台账（多维表格驱动）

每条 B/C/D 缺口在多维表格 **「PRD 反馈台账」** 表登记一行（A6 执行，通道：`lark-cli base +record-batch-create`，scope 已授权）：

| 字段 | 内容 |
|---|---|
| REQ | `REQ-###` |
| 功能点 | PRD 中的功能名（如「M-Bus 协议下发」） |
| 类别 | B 链路断 / C 待澄清 / D 建议增补 |
| 缺口描述 | 一句话（demo 侧视角） |
| demo 处理 | 已补全（形态）/ 按字面实现 / 未实现-待 PRD |
| PRD 文档链接 | 原始飞书文档 URL |
| PRD 评论状态 | 未评论 / 已评论 / 已解决 |
| 评论链接 | `drive +add-comment` 返回的 comment URL |
| demo 版本 | commit short sha |

台账表 URL 的唯一配置源：`tools/feishu_issue_table.txt`（一行 URL；**未配置 = 降级模式**：A6 整体跳过台账写入与 PRD 评论回写，仅在报告警告，不阻断质量记录主流程）。

## 4. PRD 评论回写（A6 执行）

对每条 B/C/D 缺口，向 **PRD 原始飞书文档** 发评论：

```bash
lark-cli drive +add-comment \
  --doc "<PRD 飞书 URL，取自 REQ 目录 meta 或 issue 行>" \
  --content '<评论正文>' \
  --as user
```

- **评论正文模板**（固定结构，可整体复制改写）：
  > 【UED 反馈 · REQ-###】功能点「X」：链路缺口——<缺什么>。Demo 处理：<已补全形态 / 按字面实现 / 未实现>。建议：<给 PRD 作者的具体补充建议>。Demo 预览：<链接>。
- 评论成功后把 comment 链接回填台账行（`+record-batch-update`），状态置「已评论」。
- PRD 文档链接的记录约定：PRD 从飞书拉取（`tools/fetch_feishu_doc.py`）时，源 URL **必须**存入 `00_raw` / REQ 目录的 `source.txt`（一行 URL）；没有源链接的 REQ，A6 跳过评论并在报告标注「PRD 非飞书源，评论未发」。
- **发送门禁**：评论以登录用户身份公开发到协作文档——每批发送前 A6 在会话里展示评论清单（功能点 + 正文），确认后批量发送；同 REQ 后续增量缺口可直接发。

## 5. 校验挂钩

| 规则 | 拦截的违规 | 对应条款 |
|---|---|---|
| R5 交互链完整性 | 功能点断链未补全（B 类裸奔）；必备状态集缺失 | §1 |
| 纯净性 | 补全标注（「PRD 缺省 · demo 补全」）出现在可见 UI | §1.2 |
| R4 结构覆盖 | PRD 功能点未逐条进入交互链清单 | §1 |

## 6. 边界

- 评论是**反馈**不是**改稿**：PRD 是否采纳由 PRD 作者决定，demo 侧只在台账跟踪状态（已评论 → 已解决），不代写 PRD。
- 多维表格台账与既有「UI Demo 记录」表（`tools/sync_demo_to_feishu.py` webhook 通道）是两张表两件事：前者按缺口记行（本文件），后者按 demo 记行（release 流程），不得混写。
- 非 PRD 驱动的纯组件校验页（`output/`）不触发本闭环。
