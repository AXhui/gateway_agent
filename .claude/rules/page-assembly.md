# 页面装配规则 · Page Assembly

> **适用范围**：一切由工作台 / 规划器（`engine-planner.js` + `engine-renderer.js`）产出的 demo 页面，即 L4 模块 × L5 模板的装配产物。
> **性质**：硬性约束。本规则定义「页面怎么被拼出来」的分层铁律；校验器（R2 / R3 / R4）是它的强制执行手段。
> **与既有文档的关系**：`encapsulation.md` 管 L2/L3 内部怎么封装，本文件管**页面层怎么消费 L3**；`K_patterns/` 是「怎么拼得好」的装配知识，本文件是「必须拼什么」的装配铁律；`skills/business/GOVERNANCE.md` 管 L3 包划分与依赖版本。四者互补，不重复。

## 1. 两级装配铁律

一句话：**demo 拼 L3，L3 封 L2，L2 只引 L1 令牌。**

1. **页面 → 业务组件**：demo 页面只允许「调用业务组件（L3）拼装」。页面层的工作是选模块 / 选模板、决定 L3 业务组件的**出现顺序与区块编排**、注入 `ctx`（entity / rows / route / theme）。禁止在页面层直接组合基础组件（L2）拼出业务形态 —— 那等于绕过 L3 私搭业务块，产物无法回到工程复用。
2. **业务组件 → 基础组件**：L3 只允许「调用基础组件（L2）封装」。控件一律 `ms-*` 类 + `MS_ICONS`，`atoms` 显式声明依赖序列；禁止用 `div` / `span` 重画 L2 已有能力（详见 `skills/eg71` 铁律一 / `encapsulation.md` §3）。

## 2. 分层职责表

| 层 | 只做 | 禁止 |
|---|---|---|
| 页面（`M_*` / `T_*`） | 模块增删、L3 排列顺序、栅格编排（`mod-*` 结构类）、`ctx` 注入 | 直接写 `ms-*` 组合业务形态；发明页面私有视觉常量 |
| L3 业务组件 | `atoms` 序列 + `render` / `bind` 骨架，业务框架与流程逻辑 | 重画 L2 控件；新增样式常量（配色写死例外见 `business-specific.md`） |
| L2 基础组件 | `ms-*` 视觉与交互、令牌引用 | 被 L3 / 页面覆盖视觉属性 |

## 3. 缺形态时的补位路径

页面装配时发现「某业务形态资产库里没有」：

1. **先找相似 L3**：按 `entityHint` + `tags` 检索最相似业务组件；
2. **再走 Learner 铸造**：模式 B（新业务自主生成）抽取相似组件的搭建逻辑（`atoms` 序列 + `render` 骨架）做字段迁移，生成并**注册回**资产库；
3. **然后页面再拼装**：新 L3 入库后才允许被规划器引用。

禁止的捷径：页面层一次性写死该形态（产物不可溯源、不可复用，违反本规则第 1 条）。

## 4. 校验挂钩

| 规则 | 拦截的违规 | 对应本文件条款 |
|---|---|---|
| R2 组件溯源率 | 生成稿出现未注册 class | §1 两级装配（页面私有视觉 / L3 越界类名） |
| R3 依赖闭环率 | L3 的 `atoms` 引用未封装基础组件 | §1 第 2 条 |
| R4 结构覆盖率 | 装配计划中的模块未在生成稿落地 | §2 页面层职责 |

## 5. 边界

- 页面级**纯结构**（区块顺序、栅格 gap、响应式断点）允许 `mod-*` / `bc-*` 结构类，不算「拼业务形态」。
- 单个基础组件（如一个独立 `ms-btn`）不构成业务形态时，允许出现在 L3 的 `render` 内部 —— 但页面层依然不直接引用它，一律经 L3 获得。
- 本文件不约束 `05_release/REQ-###/` 正式交付物的打包流程（见 `release.md`）。
