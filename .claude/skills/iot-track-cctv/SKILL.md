# CCTV 视频监控赛道 — 判断与思考方向

> 知识真源：`knowledge/milesight-products/security-cctv.md`（Milesight VIR-2026 安防线全景：IPC 全系列/NVR/OpenVision + AI 能力 + 参数基线）。审 PRD 前先读这份。
> 竞品对标再叠加 `knowledge/competitor-research/README.md` 的 7 维对标框架。

## 一句话定位

CCTV = 以「成像 → 编码 → 存储/传输 → 回看/告警」为闭环的视觉监控系统。审 PRD 的关键是**四段链路是否闭环、每段参数是否站得住、整体带宽与存储是否算得清**。

## 判断与思考方向（审 PRD 四段）

### 1. 成像链（前端：摄像头本身）
- 分辨率/帧率：2MP/4MP/8MP？25/30fps？是否匹配「看清什么」（人脸识别需 DPI 达标）。
- 低照度/夜视：红外距离、最低照度(lux)、是否真彩夜视/星光级。
- 宽动态(WDR)、强光抑制、背光补偿——户外逆光场景是否覆盖。
- 镜头：焦距/视场角(FOV)/变焦 vs 定焦，覆盖距离与范围是否匹配部署场景。
- 云台(PTZ)：是否需旋转/巡航/预置位。
- 防护与供电：IP 等级（户外 IP66/IP67）、PoE vs DC、防雷防浪涌。

### 2. 存储链（NVR/DVR/本地/云）
- 码率(H.264/H.265/H.265+/AV1) × 路数 × 天数 → 存储容量是否算得清？常见 PRD 硬伤：只写「存储 30 天」不写路数与码率。
- 存储形态：本地 NVR / SD 卡 / 云存储 / 混合？断网时本地是否兜底。
- 录像策略：全天 vs 事件触发（移动侦测/AI 事件）能否显著省存储。

### 3. 传输链（带宽与网络）
- 视频流上行带宽：单路码率 × 并发路数 vs 现场上行带宽是否匹配（4G 回传尤易爆）。
- 流协议：RTSP/ONVIF/GB28181/WebRTC；ONVIF 决定第三方 NVR 兼容性。
- 低带宽场景：是否需 H.265+/Smart 编码、抽帧、子码流。

### 4. 平台链（管理/告警/回放）
- 实时预览 + 回放 + 告警联动 + 权限分级是否齐全。
- 多站点/多设备统一管理；API/事件推送是否开放给第三方。

## 需求澄清必问（路由后先问，再核参数）
1. 看清目标：识别人/车牌/行为，还是仅看个画面？（决定分辨率与 AI 需求）
2. 路数与并发预览数？存多久？
3. 部署：室内/室外？固定/移动（车载）？
4. 网络：有线/PoE/4G/5G？上行带宽多少？
5. 是否要 AI（人脸/车牌/行为）？→ 是则叠加 **CV 副赛道**。

## 竞品对标方向（触发时调研，别硬答）
- 海外一线：Axis（瑞典，行业标杆）、Bosch、Hanwha（韩，原三星）、Hikvision/Dahua（中，出货量第一梯队）。
- 同源参考：Milesight 安防线（VIR-2026：Q/Pro/Panoramic/PTZ/5G/OpenVision/TrafficX 系列，参数见 knowledge/milesight-products/security-cctv.md）。
- 对标维度：分辨率/码率(H.265+)/低照度全彩/防护(IP67·IK10)/ONVIF 兼容/AI 精度(ANPR 98%·0.1s 作参照)/离网供电/单路成本。

## 产出物
需求澄清结论 + 四段链路参数核对表 + 带宽/存储测算 + 竞品基线 + 风险（尤指带宽与存储错配）。
