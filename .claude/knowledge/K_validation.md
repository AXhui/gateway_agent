# K_validation · 还原度校验清单

> 来源：根 README 第四节「还原度是怎么算的」。规则加权，「100%」不是宣传语，是可回归计算的数。
> 校验由 A5 agent 按本清单执行：发现硬编码色值或未注册 class 即降分并给出证据（落 `05_release/REQ-###/validation.md`）。

---

## 规则清单

| 规则 | 权重 | 含义 |
|---|---|---|
| R1 令牌合规率 | 30 | 组件层与生成稿中不得出现硬编码色值，必须引用 L1 令牌；间距/字号/图标尺寸必须落在红线映射表（`rules/spacing.md`）内 |
| R2 组件溯源率 | 30 | 生成稿每一个 class 都必须能在资产库中溯源 |
| R2b L3 复用率 | **一票否决** | 手写渲染函数绕过已注册 `B_*` 实现业务形态（自我生产）→ 整体判 fail，退回重做（签名表见下） |
| R3 依赖闭环率 | 25 | 业务组件的每个基础组件依赖都必须是「已封装」状态 |
| R4 结构覆盖率 | 15 | 装配计划中每个模块都必须在生成稿中落地 |

---

## R2b 形态签名表（自我生产拦截）

R2 只查「类名是否注册」，拦不住「类名合规但绕过 `B_*` 手搓业务形态」——REQ-005 的 `delConfirmHtml()` 即此盲区。R2b 补法：扫描 demo 源码中每个手写渲染函数，若其模板产出了某签名行的**全部 class**、且既不是该组件入口函数、也不调用入口 → 一票否决，报出应调用的组件与 ctx。

| 组件 | 形态签名（须全部命中） | 入口函数 | 应改为 |
|---|---|---|---|
| `B_Eg71Modal`（`bc-eg71-modal`） | `ms-modal` + `ms-btn--danger` | `renderEg71Modal` | `renderEg71Modal({ action:'delete', title, desc })` |

维护约定：
- 新增**调度器类** `B_*`（弹窗 / 向导 / 多步流程）时在本表补一行签名。
- 一次性表单弹窗（`S_Modal` + `S_Form` 直组，无 danger 确认）不在此列，允许页面层组合。

---

## 关键约束（校验强制）

1. L2/L3 任何一处出现硬编码色值即违规 —— 必须引用 L1 令牌；
1. 间距 / 字号 / 图标尺寸越出红线（见 `rules/spacing.md`：按钮间 ≥12px、卡片间 ≥16px、图标 16–44px 阶梯、字号仅 30/24/20/16/14/12）即违规；
2. 生成稿里出现的每一个 class 都必须能在五层资产库中溯源；
3. 业务形态必须调用已注册 `B_*`（按其 SKILL.md §2 契约传 ctx），手搓即一票否决；
4. 业务组件声明的每一个基础组件依赖都必须是「已封装」状态；
5. 装配计划里的每一个模块都必须在生成稿中落地；
6. **demo 纯净性**：可见 UI 不得出现 PRD 注记、交互评审指引、装配/校验痕迹（见 `rules/page-assembly.md` §5）——命中即退回 A4 重渲染。
7. **交互链完整性**：PRD 功能点断链（缺 loading/error/empty/确认等必要状态）未补全 → 退回 A4；B/C/D 缺口必须产出缺口清单（A6 台账 + PRD 评论回写的唯一输入），见 `rules/interaction-completeness.md`。

## 校验项与证据

| 规则 | 校验什么 | 证据形态 |
|---|---|---|
| R1 | 遍历组件层 + 生成稿，查 `#` / `rgb(` / 裸色值；查 gap/margin/padding/font-size/图标 width/height 是否落在 `rules/spacing.md` 红线映射表 | 列出违规 token / 越红线数值位置 |
| R2 | 提取生成稿全部 class，逐一反查 `_index.json` + 注册表 | 未溯源 class 清单 |
| R2b | 扫手写渲染函数模板，比对形态签名表 + 入口调用 | 手搓函数名 + 应调用的组件与 ctx |
| R3 | 遍历业务组件 `atoms`，核对 `implemented` 标记 | 未封装依赖清单 |
| R4 | 对比装配计划模块列表 vs 生成稿实际落地 | 缺漏模块清单 |
| R5 交互链 | 逐 PRD 功能点核对交互链（入口→操作→反馈→结果态，必备状态集见 `rules/interaction-completeness.md`）；产出缺口分类清单（B 链路断 / C 待澄清 / D 建议增补） | 缺口清单（功能点 / 类别 / demo 处理 / 建议话术），供 A6 台账 + PRD 评论 |
| 纯净性 | 扫描可见文案：评审注记（「按 PRD」）、交互指引（「点击…跳转」）、装配/校验痕迹（映射清单、R1–R5、水印）、补全标注（「PRD 缺省 · demo 补全」） | 违规文案位置 + 应迁移到的归档文件 |

## 使用时机

- 交付 `05_release/REQ-###/` 前，跑一遍 R1~R4 + R2b，把报告与 demo 一并归档。
- R2b 命中即整体 fail：分数无意义，先退回按组件契约重做再重跑。
- 样例实测基线：R1 693 项引用 0 异常 / R2 92 个 class 全部可溯源 / R3 / R4 全通过 → 100。
